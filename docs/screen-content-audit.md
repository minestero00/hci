# 화면별 표시 내용과 문구 검토 기록

검토일: 2026년 11월 4일. 참가자 UI `2026.11.04-ux4`, 콘텐츠 3.0.0, 행동 로그 telemetry 2를 대상으로 한다. 시작·동의부터 세 업무의 모든 단계, 완료·다운로드, 도움·중단·오류·복구와 연구자 작업실을 검토했다.

핵심 결정은 **참가자의 현재 행동과 응답 조건을 이해하는 데 필요한 내용을 표시하고, 정답성 보장·풀이 전략의 사전 안내·연구 운영 정보를 참가자 화면에서 줄이는 것**이다. 동의·수집 안내, 실제 과제 규칙과 문항을 불필요한 정보로 취급하지 않는다.

두 별도 검토자가 참가자 문구의 판단 유도 가능성과 역할·상태 안내의 정확성을 각각 읽었다. 두 검토 모두 연구자 도구 링크, 과제별 풀이 포인트를 예고하는 소개, 보지 않은 AI 추천을 반복해서 언급하는 안내를 지적했다. 이 검토는 내용·동작 검토이며 실제 사람에게 미친 효과나 시각적 사용성을 검증한 결과는 아니다.

## 판단 기준

| 구분 | 표시 원칙 |
|---|---|
| 수행 필수 | 지금 무엇에 답하는지, 참고할 자료, 확정의 결과, 현재 단계 가까이에 표시 |
| 동의·보관 필수 | 실제 수집 항목, 저장 범위, 중단·파일 전달 방법을 시작 전에 표시. 상세 설명은 요청 시 열람 |
| 판단 내용 | 원자료·후보·현재 요청·메모 질문을 유지. 배정된 단계에만 AI 지원 표시 |
| 운영·분석 | 배정 방식, 버전, 정답·루브릭 상세, 분석 제외·품질 표지 등은 연구자 화면·문서에 배치 |
| 상태·오류 | 실제로 해당하는 상태에서 원인 범위와 가능한 다음 행동을 표시 |
| 확신·전략 유도 가능 | 정확성 인증이나 실제 자료를 읽기 전에 핵심 풀이 차원을 예고하는 문구를 삭제·중립화 |

## 참가자 화면별 결정

| 화면·위치 | 이전 내용 또는 문제 | 결정과 현재 내용 |
|---|---|---|
| 모든 화면 footer | 연구자 도구로 바로 이동하는 링크 | **삭제.** 연구자 주소는 운영 문서에서 제공한다. 정적 자산을 비공개로 만들거나 접근 통제를 추가한 것은 아니다. |
| 모든 화면 footer | 팀 파일럿 콘텐츠 버전 노출 | **운영 문서·로그로 이동.** 화면에는 제품명과 현재 저장 범위를 남긴다. |
| 상단 상태 | 저장 방식과 저장 완료를 혼동할 여지 | **상태별 표시.** 자동 저장 사용 가능·저장 대기 중·저장 중·자동 저장·임시 보관·저장 확인 필요를 구분한다. |
| 시작 제목 | 홍보성 제목과 문구 | **중립화.** ‘세 가지 업무에 응답해 주세요.’로 해야 할 일을 알린다. |
| 시작 업무 소개 | 명단·인력·권한·고정본·작업 의존관계를 미리 예고 | **업무명만 유지.** 행사 운영·문서 공유·제출 일정. 실제 규칙은 해당 업무 자료에서 읽는다. |
| 시작 업무 목록 | 01~03 번호·화살표와 무작위 순서 안내 | **삭제.** 실제 진행 순서나 클릭 메뉴로 오인할 수 있는 표시를 줄인다. 실제 순서는 진행 화면에서 표시한다. |
| 시작 절차 | ‘일부 실행에는 AI 지원문’ | **삭제.** 다른 조건의 존재를 소개하지 않는다. 실제 AI 지원이 표시될 때 출처 라벨을 유지한다. |
| 시작 절차 | ‘AI 지원 없이 원자료로 응답’ | **원자료와 새 요청에 응답하는 절차로 표현.** 이후 점수 예상에 필요한 자원 범위는 예상 점수 단계에서 알린다. |
| 참여 링크 | 정상 초대와 자유 체험의 구분 | **유지.** 초대는 참가자 코드 확인, 자유 체험은 본 수집과의 구분을 안내한다. |
| 잘못된 참여 링크 | 자유 체험처럼 설명하고 시작 버튼만 비활성화 | **오류 전용 화면.** 참여 링크를 다시 받는 행동과 이전 기록 보관만 제공한다. 다른 참여로 우회시키지 않는다. |
| 익명 코드 | 이름·학번·연락처를 입력하지 말라는 안내 | **유지.** 실제로 필요한 익명 코드만 요청한다. |
| 시작 전 동의 | 상세 로그를 모두 삭제하면 수집 사실을 알기 어려움 | **유지·정확화.** 동의 후 기록 시작, 응답·수정본·관찰 행동, 수동 파일 전달을 요약한다. |
| 기록 상세 | 문자 키·클립보드·선택 원문과 답안 본문의 구분 | **유지.** 답안·수정본에는 본문이 포함되지만 자동 조작 로그는 키 종류·발생·길이 등을 기록함을 설명한다. |
| 기록 상세 | ‘IME’ | **일상 언어로 수정.** ‘한글 조합 입력 유형’으로 설명한다. |
| 저장 안내 | 임시 보관 환경에서도 자동 저장·재접속을 보장 | **저장 방식에 따라 분기.** 임시 보관에서는 현재 탭만 유지되며 새로고침·닫기 전에 파일 보관이 필요하다고 표시한다. |
| 기존 실행 | 재개·이전 파일 보관 | **기록이 있을 때 유지.** 임시 보관은 ‘현재 탭의 기록’으로 표시한다. |
| 연습 | ‘분석에서 제외되는 연습’ | **삭제.** 연습 이벤트·수정본도 원본에 남는다. 화면은 조작 연습임을 설명한다. |
| 연습 | 무관한 단어 선택·짧은 메모 | **유지.** 실제 과제 정답을 가르치지 않고 조작을 익힌다. |
| 연습의 4점 안내 | 최초 실행안 점수의 포함 여부가 암묵적 | **명확화.** 각 업무의 후속 선택형 1+1점과 인계 메모 2점이며 최초 실행안은 제외한다. |
| 공통 메모 채점 안내 | 관계 연결의 세부 채점 표현 | **일반 범위로 간결화.** 판단 근거의 정확성·충분성에 따른 0~2점과 모르겠음 0점을 알린다. 업무별 정답·경계 예시는 제공하지 않는다. |
| 원자료·역할·목표 | 실제로 답을 도출하는 데 필요한 조건 | **모두 유지.** 과제를 정의하는 규칙은 없애지 않는다. |
| 원래 후보 절차 | 평가 중에도 남는 원자료 표 | **유지.** 최초 추천을 외워야만 답할 수 있는 형태가 되지 않도록 원자료로 제공한다. |
| AI 지원 | ‘연구팀이 정확성을 검토한 고정 지원문’ | **삭제 상태 유지.** 정확성 인증과 일반적인 AI 불신 경고를 추가하지 않는다. |
| AI 지원 라벨·본문 | 추천과 근거 자체 | **유지.** 실제 연구의 지원 내용이며 지원 조건의 최초 판단·예상 단계에만 표시한다. |
| 원자료 조건 지원 칸 | ‘충분히 살펴본 뒤 실행안을’ 반복 | **현재 단계에 맞게 수정.** 선택 단계는 실행안 선택, 예상 단계는 다음 평가 범위를 확인하도록 안내한다. |
| 후속 요청·메모 상단 | ‘이전 추천·설명이 제공되지 않는다’ | **별도 안내 카드 삭제.** 보지 않은 추천을 언급하지 않는다. 현재 요청·원자료·응답 안내만 남긴다. |
| 예상 점수 | ‘이후 평가에서 몇 점’ | **대상 명확화.** 이번 업무의 후속 요청 두 개와 메모 점수를 묻는다. 세 업무 전체나 최초 선택의 정오로 혼동하지 않도록 한다. |
| 예상 점수 | 참고 가능한 자원과 4점 범위 | **유지.** 다음 단계는 왼쪽 원자료만 참고하고 최초 선택은 점수에 포함되지 않는다고 알린다. |
| 정신적 노력 | 측정 문항·1~7 응답 | **유지.** 측정하는 내용과 척도를 바꾸지 않는다. |
| 후속 요청 | 원래 상황에 이번 변경만 적용 | **유지.** 독립 변경이라는 과제 규칙을 해당 단계에 표시한다. |
| 메모 | 원래 업무로 돌아가 작성 | **유지.** 두 변경을 합쳐 작성하는 오류를 막는다. |
| 메모 실제 질문 | 업무별로 요청하는 관계·근거 | **유지.** 질문 자체를 일반적인 ‘이유를 쓰세요’로 축소하면 평가 대상이 달라진다. |
| 메모 입력 보조 | 과제별 풀이 차원을 다시 강조하는 placeholder·‘조건의 연결을 봅니다’ | **중립화.** 입력 안내와 짧은 문장·항목 허용, 글자 수를 표시한다. 실제 질문은 그대로 둔다. |
| 메모 버튼 | ‘메모 제출’ | **‘메모 확정’으로 통일.** 브라우저 안 확정과 외부 전달을 구분한다. |
| 공통 확정 안내 | 확정 후 수정 불가 | **유지.** 실제 행동의 결과다. |
| 도움말 | ‘긴 글보다 조건 관계가 중요’ 반복 | **삭제.** 자료 접근·확정·독립 요청·메모 기준 상황·중단 방법만 안내한다. |
| 진행·완료의 보조 버튼 | 완료 후에도 도움·잠시 나가기 표시 | **진행 중에만 표시.** 완료 화면은 파일 보관·전달에 집중한다. |
| 완료 | 별도 채점 운영 설명 | **삭제.** 응답 파일 확인과 담당자 전달을 직접 안내한다. |
| 완료 | 다운로드·전달 안내의 중복 박스 | **삭제.** ‘파일 확인 → 담당자 전달’ 두 단계와 자동 제출이 아님을 유지한다. |
| 완료 다운로드 표시 | 이전 실행·중간 파일 다운로드를 최종 파일 요청으로 혼동 | **실행·응답 단계별로 구분.** 현재 실행의 완료본을 요청한 경우에만 해당 상태를 표시한다. |
| 오류·복구 | 사용자 행동과 무관한 내부 예외 문구 | **화면에서는 축소.** 원인 이름은 진단 이벤트에 남기고 보관·재시도·담당자 연락을 안내한다. |
| 복원 실패 | 참가자를 연구자 도구로 안내 | **담당자에게 알리도록 수정.** 참가자가 루브릭 화면으로 이동할 필요가 없다. |
| 잠금 실패·상실 | 항상 다른 탭 때문이라고 단정 | **원인 범위를 정확히 표현.** 다른 탭 사용 또는 저장 상태 확인 실패를 안내하고 재연결·복구 파일을 제공한다. |
| 임시 보관 중 나가기 | ‘같은 브라우저에서 이어하기’ 보장 | **동일 탭 내 재개로 제한.** 새로고침·닫기 전 파일 보관을 알린다. |
| 좁은 창 | 참여 제한 때문에 복구 행동까지 숨김 | **보관 버튼·저장 경고 유지.** 넓은 창에서 진행하되 현재 기록 보관은 가능하다. |

## 연구자 화면별 결정

| 화면·위치 | 결정 |
|---|---|
| 초기 본문 | ‘연구자 기록을 불러오는 중’ 상태를 표시한다. |
| 기록 가져오기 | 응답·채점·보관 등 여러 JSON을 받으므로 ‘JSON 파일 가져오기’로 이름을 맞춘다. |
| 수집·행동 탐색 | 조건·완료·메모·로그 수, 품질 경고와 원기록을 유지한다. 실제 읽기·주의·이해로 해석하지 말라는 정의도 이 위치에 유지한다. |
| 누적 초대 목록 | ‘현재 초대 배치’ 대신 ‘생성한 참여 링크’로 표시한다. 여러 배치가 누적됨을 잘못 표현하지 않는다. |
| 초대 목록 내보내기 | ‘링크 목록 JSON’은 전달용임을 알린다. 작업실 복원은 전체 보관 JSON을 사용한다. |
| 저장 실패 | 목록 전달과 작업실 복원을 구분해 보관 행동을 안내한다. 다운로드 요청 메시지가 저장 실패 경고를 덮지 않는다. |
| 채점할 메모가 없음 | 빈 묶음 생성을 비활성화하고 메모가 있는 응답·채점 묶음을 가져오도록 안내한다. |
| 독립 채점 | 조건·예상·행동·타 채점 점수를 답안 영역에서 표시하지 않는다는 범위를 알린다. 별도 브라우저에서 채점 묶음을 사용하는 절차를 유지한다. |
| 합의 채점 | 두 독립 점수를 보고 합의한다는 제목·설명을 사용한다. 독립 채점 안내와 혼동하지 않는다. |
| 채점 기준·경계 답안 | 연구자에게 유지한다. 역할 선택·집중 화면이 인증이나 기술적 독립성을 보장한다고 표현하지 않는다. |
| 분석 요약 숫자 | 초대 참여와 팀 체험 포함 전체 수의 범위를 라벨로 구분한다. 실제 CSV는 포함 옵션에 따른다. |
| 연구자 파일 다운로드 | 요청 후 다운로드 목록 확인을 안내한다. 파일 저장 성공이나 외부 제출 완료로 단정하지 않는다. |
| 중복·충돌·미채점 | 기존 기록 보존, 결측과 0점, 최종 파일 수집·복구 절차를 유지한다. |

## 변경하지 않은 연구 내용

원자료의 명단·인력·준비 시간, 권한 적용·고정본 규칙, 작업 의존·소요 시간과 제출 확인은 가상 업무의 판단 조건이다. 선택지에 가능한 결과와 설명이 포함되는 것도 문항 구조의 일부다. 이 내용과 실제 AI 추천·근거, 메모의 질문·루브릭은 유지했다. 화면에서 연구자용 설명을 덜어내는 것과 정답을 도출할 자료를 없애는 것은 구분한다.

일반적인 점수 정의는 예상 점수를 응답하는 데 필요하므로 남겼다. 과제별 정답·구체적인 경계 예시는 연구자에게만 표시한다. 동의·로그 안내는 판단에 영향을 줄 가능성이 있다는 이유로 숨기지 않는다. 이름·보관 기간·전달 후 철회 절차 등 실제 운영 값은 연구 담당자가 결정해야 하며 임의로 만들어 넣지 않았다.

## 검증 범위

검증 대상 구현은 [67a0f76ab64a9995b6ed47c1f5258c44e4fc5996](https://github.com/minestero00/hci/commit/67a0f76ab64a9995b6ed47c1f5258c44e4fc5996)이다. 로컬 `npm run check`와 [GitHub Actions 41752723160](https://github.com/minestero00/hci/actions/runs/41752723160)에서 전체 43개 시험과 모듈 구문 검사·14개 정적 파일 빌드가 통과했고 배포도 완료했다. 공개 루트의 ux4 버전과 14개 배포 파일의 HTTP 정상 응답·로컬 빌드 바이트 일치를 확인했다. 이 검증 기록을 추가하는 후속 문서 커밋은 런타임을 변경하지 않는다.

- 실제 DOM 흐름으로 AI 지원·원자료 조건 각각의 16개 확정 단계를 진행하며, 단계별 AI 노출·점수 예상 대상·연구자 링크 부재와 원본 내보내기를 확인한다.
- 중간 파일을 먼저 내려받아도 완료본을 이미 받았다는 안내가 나타나지 않는지 확인한다.
- 잘못된 초대 링크에서 자유 체험 양식이 나타나지 않는지 확인한다.
- 임시 보관 환경의 시작·동의·상세 안내·좁은 창·나가기·동일 탭 재개 설명을 확인한다.
- 연구자 빈 채점·역할별 제목·목록/복원 안내·다운로드 피드백과 기존 저장·충돌 회귀 시험을 확인한다.

실제 Chrome의 화면 렌더링·접근성 트리·스크롤 체감과 사람의 문구 이해도는 이 DOM 검증에 포함되지 않는다. 이전 컴퓨터 사용 도구의 정책 차단을 우회하지 않았으며, 시각 검증·사람 파일럿의 대체라고 주장하지 않는다. 정확한 커밋의 검증·배포 결과는 [워크플로 실행 기록](https://github.com/minestero00/hci/actions/workflows/pages.yml)에서 확인한다.
