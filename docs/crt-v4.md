## 기존 자료 보존

v3 참가자·연구자 HTML을 `legacy-v3.html`, `legacy-v3-research.html`로 보존했다. 기존 v3 자바스크립트와 DB는 계속 사용한다. v3 테스트는 이 복구 진입점을 검증하도록 경로만 바꿨다. BrowserStore, ResearchStore, Recorder에는 v4용 DB 이름과 검증/단계 함수를 주입할 수 있도록 확장했으며 기본값은 v3 동작을 유지한다.

새 DB는 `hci-crt-v4`, 연구자 DB는 `hci-crt-research-v4`, 활성 키는 `hci-crt-v4-active`다. v4 형식 검증은 v3 파일을 거부하고 이전 화면을 안내한다. 로컬 기록을 나중에 서버 수집 모드에서 재개하면 기존 자료 전송에 대한 별도 체크를 먼저 받는다.

## 초기 구현 당시 남은 검증과 운영 결정

실제 서버에는 이번 변경을 배포하지 않았다. 새 중앙 배정은 새 Firestore 규칙 배포 후 사용해야 한다. Pages 배포 뒤 실제 참가자용 서버 수신과 지정 연구자의 Google 로그인·가져오기 왕복, 공용 기기의 다음 참가자 계정 교체를 확인해야 한다. 기존 v3 라이브 시험을 v4 라이브 증거로 대신하지 않는다.

담당자·연락 방법·보관 종료일·모집 마감·보상·적격/제외 기준·표본 부족 전환은 팀에서 실제 모집 전에 고정해야 한다. 새 자극의 난이도·노출·이해·실제 소요시간·채점 일관성은 별도 사람 파일럿 6~10명으로 확인한다.

중앙 배정은 익명 UID별 한 번이며 같은 사람이 브라우저를 바꾸어 재참여하는 것을 완전히 막지 못한다. 연구자 권한 계정은 배정표를 볼 수 있으므로 배정표 관리와 참가자 진행을 다른 담당자로 나눈다. 참가자에게 미래 슬롯/목록은 숨기지만 트랜잭션 검증을 위한 현재/과거 익명 슬롯 단건 읽기는 허용한다. 정적 저장소와 키의 공개성, 클라이언트 응답 변조 가능성도 남는다.

수신 확인은 그 시점의 응답·행동 묶음 확인이다. 이후 생긴 이벤트까지 모두 영구 보관했다는 뜻이 아니다. 브라우저 강제 종료·저장소 삭제·기기 장애 시 최근 미전송 자료를 보장하지 않는다. 원본 JSON과 복구 안내를 유지한다.

### 증거의 범위와 사람에게 남은 항목

배정표 게시와 `loadRecords`의 실제 응답/수신 검증은 로컬 CLI 관리자의 IAM 인증으로 수행했다. 가져오기 조회는 검증용 run으로 한정했다. 이것은 Google 브라우저 사용자에게 Firestore 규칙이 허용되는지의 증거가 아니다. 실제 작업실의 Google 버튼이 올바른 프로젝트의 로그인 화면을 여는 것까지 확인했으며, 검증 브라우저에 로그인된 Google 세션이 없어 계정 인증 완료는 수행하지 않았다. CLI OAuth 토큰은 Firebase Google 로그인과 audience가 달라 이를 대신 사용할 수 없었고, 인증 설정·허용 audience·계정 권한을 바꾸지 않았다.

사람이 확인할 항목은 다음과 같다.

1. 허용 연구자가 직접 Google 로그인 후 작업실에서 서버 가져오기·중앙 배정표 생성을 확인한다.
2. 사람 파일럿 6~10명으로 문항 난이도·예상 점수 이해·채점 일치도·실제 소요시간과 실제 사용 기기를 확인한다.
3. 담당자·연락처·보관 종료일·모집 마감·보상·적격/제외 기준과 배정표 관리자/진행자 분리를 확정한다.
