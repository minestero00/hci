# 판단 워크스페이스 과제 원문과 채점 기준

콘텐츠 버전: 3.0.0. 이 문서는 GitHub Pages 팀 파일럿의 실제 문항을 기록한다. 원문은 [content.mjs](../web/content.mjs), 연구자용 정답·루브릭은 [research-key.mjs](../web/research-key.mjs)가 기준이다.

## 현재 상태와 설계 범위

이전 [파트별 평가](task-review.md)에서 지적된 문항 구조를 보완했다. 세 과제는 여전히 연구용 가상 업무이며 실제 제품·학교 규정·예약 조건을 재현한다고 주장하지 않는다. 정답과 계산은 확인했지만 사람의 실제 난이도·현실감·채점 일치도는 파일럿에서 검증해야 한다.

| 파트 | v3에서 바꾼 평가 응답 |
|---|---|
| 행사 예약 | 원래 장소 이름만 반복하지 않고 새로 가능한 장소와 최종 선택의 조합, 추가 인력의 실제 배치를 선택한다. |
| 공유 권한 | 지윤의 유효 권한과 멘토 조치를 함께 판단하고, 제출 후 원문·고정본에 대해 서로 다른 후속 조치를 선택한다. |
| 제출 계획 | 새 의존관계에 맞춰 녹화를 뒤로 미루는 합리적인 조정을 정답으로 인정한다. 기존 카드 준수 여부는 채점하지 않는다. |

사례마다 후속 요청 선택형 두 개를 각 1점, 원래 업무 인계 메모를 0~2점으로 채점한다. 최초 계획 선택은 별도 보조 결과이며 독립 수행 4점에 넣지 않는다. 예상 점수는 문항을 보기 전에 0~4점을 0.5점 간격으로 받는다. 후속 요청은 각각 원래 상황에서 독립적으로 적용한다. 후속 요청 순서가 뒤바뀌어도 해석이 같아야 한다.

설명 점수는 두 기준 관계를 모두 정확히 연결하고 결론에 상충 오류가 없으면 2점, 유효한 부분근거는 있지만 불완전하거나 상충 오류가 있으면 1점, 유효한 근거가 없으면 0점이다. 숫자 반복·분량·문체는 가점하지 않는다. 실제 답이 없는 결측과 모르겠음 0점은 구분한다.

주 분석의 실제 점수는 선택형 합계와 인간 합의 설명 점수를 더한 값이다. AI 점수와 인간 합의·AI 평균은 보조 분석으로 별도 계산한다. 설명 재현과 새로운 조건 적용 점수를 함께 보존하고, 총점만으로 순수한 전이 능력을 주장하지 않는다.

정적 Pages 파일은 공개 자료다. 참가자 화면은 연구자 키를 불러오지 않지만 기술적 비밀성이나 응답의 서버 자동 수집을 보장하지 않는다. 참가자는 전체 응답·로그 JSON을 내려받아 연구자에게 전달한다.

## 체험행사의 예약안을 정해주세요

역할: 동아리 예약 담당자. 운영진의 요청과 예약 조건을 확인하고, 행사에 사용할 운영안을 정합니다.

### 팀 요청 운영진 단체방

금요일 18:00–20:00에 신입 부원 체험행사를 진행합니다. 참가자 36명 중 외부 초청자는 12명입니다. 외부 참가자의 최종 명단은 행사 당일 15:00에 확정됩니다.

운영진은 두 명입니다. 한 명은 진행, 다른 한 명은 재료 배부와 참가자 도움을 맡습니다. 두 사람 모두 행사 내내 활동 공간을 떠날 수 없습니다.

장소에는 17:30부터 입실할 수 있습니다. 여섯 팀이 동시에 활동할 수 있도록 18:00까지 준비를 끝내주세요.


### 예약 안내 조건과 선택 기준

세 안 모두 36명과 여섯 팀의 활동 공간·장비를 제공하며 예약 시간도 같습니다.

입구 담당이 필요한 안에서는 한 사람이 행사 내내 입구를 맡아야 합니다. 활동 공간의 업무와 겸할 수 없습니다.

명단·인력·준비 시간 조건을 모두 충족하는 안 중, 주최 측 자리 준비 시간이 가장 짧은 안을 선택해주세요. 아래 준비 시간은 고정입니다.

| 세미나실 | 전날 17:00까지 제출 · 이후 추가·교체 불가 | 장소 직원 | 30분 |

### 고정 AI 지원

추천 · 활동실 예약

명단이 행사 당일 15:00에 확정되므로, 전날 제출이 마감되는 세미나실은 조건을 맞출 수 없습니다.

창작실에는 입구 전담자가 필요하지만 현재 두 운영진은 모두 활동 공간을 떠날 수 없습니다.

활동실은 명단을 행사 전까지 수정할 수 있고 입구 확인도 장소 직원이 맡습니다. 준비 15분도 입실 후 확보된 30분 안에 끝납니다.

### 후속 요청 외부 참가자 명단이 일찍 확정됐습니다

전체 외부 참가자 명단이 행사 전날 16:00에 확정되어 제출됩니다. 이후 추가·교체는 없습니다. 다른 조건은 원래대로입니다.

예약 담당자에게 보낼 검토 결과로 맞는 것은 무엇인가요?

| seminar-activity | 세미나실·활동실 가능 · 활동실 예약 | 세미나실도 가능하지만 창작실은 인력이 부족하므로, 준비시간이 짧은 활동실을 예약한다. |

| activity-still | 활동실 예약 · 입구는 장소 직원이 담당 | 기존 두 운영진이 활동 공간을 떠날 수 없으므로, 추가 인력이 있어도 창작실은 불가능하다. |

### 원래 업무 인계 메모

원래 상황으로 돌아갑니다. 예약할 운영안과, 다른 두 안을 선택할 수 없는 이유를 다음 운영진에게 인계할 짧은 메모로 남겨주세요. 명단과 인력의 관계를 포함해주세요.

채점 기준 관계:

1. 세미나실의 전날 명단 마감과 행사 당일 최종 명단 확정이 맞지 않아 원래 상황에서는 예약할 수 없음을 연결한다.
2. 창작실은 입구 전담자가 필요하지만 기존 두 운영진은 활동 공간을 떠날 수 없어 배치할 인력이 없음을 연결한다.

| 점수 | 기준 |
|---|---|
| 0 | 유효한 기준 관계를 설명하지 못함. 이름만 제시, 모르겠음, 또는 준비시간만 보고 필수조건을 무시한 설명. |
| 1 | 두 기준 중 하나의 유효한 관계를 설명하거나, 유효한 부분근거는 있지만 구분이 불완전함. 결론에 상충 오류가 있으면 최대 1점. |
| 2 | 활동실을 선택하고 명단 마감 충돌과 입구 인력 부족을 모두 정확히 연결함. 활동실의 가능 여부와 상충하는 오류가 없음. |

| 점수 | 경계·예시 답안 | 판단 근거 |
|---|---|---|
| 2 | 활동실로 예약하겠습니다. 세미나실은 명단 확정 전에 제출이 마감되고, 창작실은 두 운영진이 활동 공간에 있어 입구를 맡길 사람이 없습니다. | 두 제외 근거와 올바른 선택을 연결했다. |
| 2 | 명단은 당일에야 정해져 전날 마감인 곳은 안 됩니다. 입구 전담자도 따로 없으니 직원이 입구를 맡고 명단 수정이 가능한 활동실이 맞습니다. | 수치를 반복하지 않았지만 두 관계가 동등하게 드러난다. |
| 1 | 세미나실은 명단이 확정되기 전에 제출해야 해서 안 됩니다. 활동실을 예약하겠습니다. | 명단 관계는 정확하고 인력 관계는 빠졌다. |
| 1 | 창작실 입구를 맡을 여분의 사람이 없습니다. 활동실로 하겠습니다. | 인력 관계는 정확하고 명단 관계는 빠졌다. |
| 1 | 세미나실은 명단 확정 전에 마감됩니다. 그래도 준비가 없는 창작실을 예약하겠습니다. | 명단의 유효한 부분근거는 있지만 인력 조건을 놓쳐 결론이 틀렸다. |

| 0 | 활동실 | 선택 이름만으로는 설명 점수를 주지 않는다. |

## 발표 원고의 공유 설정을 정해주세요

역할: 팀 발표의 공유 설정 담당자. 현재 권한과 도구 규칙을 확인하고, 팀의 편집·검토 요청을 충족할 설정안을 정합니다.

### 팀 요청 발표팀 채널

제출용 원고는 오늘 19:40까지 수정·저장할 예정입니다. 교수님은 20:00에 생성한 제출용 고정본을 봅니다. 그때 제출한 내용은 이후 바뀌면 안 됩니다.

팀원 네 명 모두 각자 맡은 부분을 20:00 이후에도 같은 원문에서 계속 편집해야 합니다. 멘토는 지난주에는 본문을 수정했지만, 오늘은 원문에 댓글만 남길 수 있어야 합니다.


### 현재 상태 팀 발표 폴더

| 대상 | 현재 상태 |
| --- | --- |
| 작업 폴더 | 팀 발표 |
| 폴더 안 작업 문서 | 발표 원고 |
| 팀원 4명 | 폴더 편집 멤버 |
| 외부 멘토 1명 | 폴더 편집 멤버 |
| 별도의 문서 초대 | 없음 |


### 도구 안내 이 작업공간의 공유 규칙

- 폴더 권한은 안의 문서에도 적용됩니다. 폴더와 문서의 권한이 다르면 더 넓은 권한을 적용합니다. 범위는 보기 < 댓글 < 본문 편집입니다.
- 폴더 멤버에서 제거한 사람도 문서에 개별 초대할 수 있습니다. 댓글 권한은 보기·댓글이 가능하고 본문 편집은 불가능합니다.
- 제출용 고정본은 지정 시각에 서버에 저장된 본문을 복사한 보기 전용 자료입니다. 이후 원문 수정은 고정본에 반영되지 않습니다. 교수님은 고정본 링크를 보고, 멘토는 원문에 댓글을 남깁니다.
- 고정본 생성은 원문을 잠그지 않습니다. 원문 본문 잠금은 팀원과 멘토 모두의 본문 편집을 막으며 보기·댓글은 허용합니다.

원래 요청에서 검토할 제안입니다. 후속 요청에서는 필요한 경우 새 조건에 맞게 조정할 수 있습니다.

| 검토안 | 제안된 절차 |
|---|---|
| 폴더 멤버 제거 후 문서 댓글 초대 | 멘토를 폴더에서 제거하고 원문 댓글로 초대합니다. 20:00 고정본을 생성하며 원문은 잠그지 않습니다. |
| 폴더 멤버 유지 후 문서 댓글 초대 | 멘토의 폴더 멤버 자격을 유지하고 원문 댓글로도 초대합니다. 20:00 고정본을 생성하며 원문은 잠그지 않습니다. |
| 폴더 멤버 제거 후 원문 본문 잠금 | 멘토를 폴더에서 제거하고 원문 댓글로 초대합니다. 20:00에 원문 본문을 잠그고 고정본을 생성합니다. |
